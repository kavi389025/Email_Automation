Complete Specification Project Overview & Tech Stack

Project Overview Build a full-stack AI-Powered Email Management Application called Intelligent Email Assistant (MailSense AI) that connects to a real email service (Gmail) over OAuth and lets users view, search, organize, and manage their inbox while using AI to summarize long emails and generate context-aware replies. The platform must never ask for email passwords, must use OAuth exclusively for Gmail access, must keep all tokens and secrets server-side and encrypted, and must ship as a working, deployed, frontend-backend integrated application.

Tech Stack Frontend: Next.js (Pages Router), React 19, Tailwind CSS, Zustand, Axios, lucide-react icons, and a rich-text/editable text area component for reply editing. Backend: Node.js, Express, MongoDB, Mongoose, JSON Web Tokens, Google APIs Node.js client (googleapis) for Gmail, helmet, morgan, compression, express-validator, express-rate-limit, and bcryptjs. AI Integration: OpenRouter API and Google Generative AI SDK (Gemini) for summarization, reply generation, tone rewriting, and classification. Integrations: Google OAuth 2.0 for Gmail (readonly + send + modify scopes). Sensitive credentials (access token, refresh token, client secret) are encrypted at rest with an application-level key and never exposed to the frontend or committed to source control.

Authentication, Email Management, and AI Layer

Authentication The authentication system must support registration, login, JWT-based session handling, protected routes, an /auth/me profile endpoint, password hashing with bcrypt at cost factor 12, and persistent login state on the client through Zustand. Gmail account connection is a separate, subsequent step performed after app login, via Google OAuth consent.

Email Account Connection (OAuth) After logging into the app, the user connects their Gmail account through a "Connect Gmail" action that redirects to Google's OAuth consent screen. On successful consent, Google issues an authorization code that the backend exchanges for an access token and refresh token. These tokens are encrypted with CREDENTIAL_ENCRYPTION_KEY and stored against the user's account, never returned to or stored in the browser. A missing, revoked, or expired token must surface as an explicit GMAIL_NOT_CONNECTED or AUTH_EXPIRED error rather than a silent failure or generic 500, and the frontend must prompt reconnection.

Email Dashboard / Inbox Users must be able to view a paginated inbox synced from Gmail, open individual emails, and view full threads with correct chronological ordering and sender/recipient metadata. The dashboard must support search (subject, sender, body keywords, date range) and basic management actions: mark read/unread, star/unstar, archive, delete (move to trash), all of which must be reflected back to the real Gmail account via the Gmail API, not just locally.

Email Composition & Sending Users must be able to compose a new email, reply to, or forward an existing email, with support for To/Cc/Bcc, subject, and body, and send it through the Gmail API under the authenticated user's identity. Sent items and activity must be recorded in the application's own history for auditing, independent of Gmail's own Sent folder.

AI Features Summarization: Given an email or thread, the backend must call the configured AI provider to produce a concise summary (key points, sender intent, any requests) that renders above or beside the full email body. Reply Generation: Given an email and optional user instructions, the backend must generate a draft reply. The user must be able to review and edit the AI-generated draft in a normal editable text field before sending — the AI never sends on the user's behalf without explicit confirmation. Provider Fallback: The AI generation service must prefer OpenRouter when OPENROUTER_API_KEY is set, fall back to Google Gemini when GEMINI_API_KEY is set, and fall back to a deterministic extractive summary/template-based reply when neither key is available, so the app remains usable without live AI credentials.

Bonus / Phase-2 AI Features (optional, additive) AI email classification (e.g., work, personal, promotions, updates), automatic priority detection, spam/phishing flagging, important-email detection, AI-generated subject lines, tone selection (Professional / Friendly / Formal / Concise) for generated replies, grammar correction and rewriting of drafts, an "Explain This Email" mode, extraction of action items and dates/deadlines, calendar-event suggestion from extracted dates, smart natural-language email search, bulk email actions, reusable email templates, multiple connected Gmail accounts per user, Outlook as a second provider behind the same integration interface, voice-to-email dictation, email analytics (volume, response time, category breakdown), a daily digest summary, and AI-based inbox prioritization ordering.

Backend Architecture & Database Collections

Backend Architecture Routes: Handles HTTP routing, request validation via express-validator, and middleware composition (auth, validation, error handler). Controllers: Request parsing and response shaping only (never talks directly to MongoDB or the Gmail API). Services: Business logic ownership (auth, Gmail sync, email actions, AI generation, token encryption/refresh, activity logging). Integrations Layer: Wraps the Gmail API (and any future provider such as Outlook) behind a common interface defined in baseEmailProvider.js, exposing fetchMessages, fetchThread, sendMessage, modifyLabels, and searchMessages. AI Layer: Holds summarizer, replyGenerator, and classifier modules, each calling the shared aiService with provider fallback. Config Layer: Centralizes environment variables, MongoDB connection (with in-memory fallback), Google OAuth client setup, and encryption key handling.

Database Collections Users: Stores authenticated app users (name, email, password with select: false, role, lastLogin). EmailAccounts: Stores connected Gmail accounts per user (owner, provider: gmail | outlook, emailAddress, isConnected, scopes, encrypted access/refresh tokens, expiresAt). EmailCache: Stores a locally cached, searchable copy of synced messages/threads (owner, accountId, gmailMessageId, threadId, subject, snippet, from, to, cc, labels, isRead, isStarred, receivedAt). AIActivity: Stores a record of every AI action performed (owner, emailId, type: summary | reply | classification | tone-rewrite, prompt, output, provider used, createdAt). ActivityLog: Stores user-facing history/audit trail (owner, action: sent | archived | deleted | starred | replied, emailId, metadata, timestamp). Notifications: Stores alerts for the user (owner, type, title, message, isRead).

API Endpoints

Health and Auth GET /api/health – System heartbeat and status check. POST /api/auth/register – Register a new user account. POST /api/auth/login – Authenticate user and issue JWT. GET /api/auth/me – Fetch current user profile.

Gmail Connection GET /api/email-accounts – List connected email accounts and their status. GET /api/email-accounts/oauth/start – Initiate Google OAuth consent flow. GET /api/email-accounts/oauth/callback – Handle Google OAuth callback, exchange and store tokens. DELETE /api/email-accounts/:id – Disconnect a Gmail account.

Emails GET /api/emails – List inbox messages with pagination, filters, and search. GET /api/emails/:id – Fetch a single email's full content. GET /api/emails/thread/:threadId – Fetch a full thread in order. PATCH /api/emails/:id – Update flags (read/unread, starred, archived). DELETE /api/emails/:id – Move an email to trash. POST /api/emails/send – Send a new, reply, or forwarded email.

AI POST /api/ai/summarize – Summarize a given email or thread. POST /api/ai/generate-reply – Generate a draft reply (optionally with tone/instructions). GET /api/ai/activity – List AI activity history for the user.

Notifications & History GET /api/notifications – List user notifications. GET /api/activity – List account activity/history log.

UI, Security, Outcome, and Codex Instructions

UI and UX Requirements The UI must use a clean, modern inbox aesthetic with Tailwind, be fully responsive, include loading states and skeleton loaders for email lists and AI panels, present threads with clear sender/timestamp grouping, surface the AI summary above the email body with a visible "Generate Reply" action, always render AI-generated replies in an editable field before send, and provide a notifications/activity drawer accessible from the AppShell.

Security Requirements The application must hash passwords with bcrypt at cost 12, sign and verify JWTs with JWT_SECRET, never request or store the user's email password, use OAuth exclusively for Gmail authentication and access, encrypt Gmail access and refresh tokens at rest with CREDENTIAL_ENCRYPTION_KEY, set HTTP security headers via helmet, apply CORS limited to CLIENT_URL, rate-limit auth and OAuth endpoints via express-rate-limit, validate every request body with express-validator, never log decrypted tokens or raw email content, never expose client secrets or API keys in frontend code or commit them to source control, and treat any missing/expired/revoked Gmail credential as an explicit GMAIL_NOT_CONNECTED / AUTH_EXPIRED error rather than a generic 500.

Final Expected Outcome The completed platform must let a user log in, securely connect their real Gmail account via OAuth, browse and search their inbox, open a long email and get an AI summary in seconds, generate an AI-drafted reply, edit it, and send it — all backed by real Gmail API calls, encrypted credential storage, and a full activity history. The final application should feel like a lightweight, AI-augmented webmail client, deployed and working end-to-end with a proper frontend-backend integration.

Codex & AI Agent Implementation Instructions The AI coding agent must build the application phase by phase, follow the folder structure strictly, keep controllers thin and push logic into services, never call MongoDB or the Gmail API directly from a controller, wrap all Gmail access behind the baseEmailProvider interface so a second provider (e.g., Outlook) can be added later without touching callers, treat every secret as process.env and never hardcode or expose it to the client, use an in-memory store fallback when MongoDB is unavailable so local dev still works, ensure AI-generated replies are always returned to the frontend as editable drafts rather than auto-sent, log every AI action to AIActivity and every mutating email action to ActivityLog, and report the list of files created or changed at the end of every phase.
